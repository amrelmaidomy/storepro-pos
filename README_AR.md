# StorePro — النسخة المحلية المحسّنة

برنامج Python لجهاز Windows واحد. يعمل بدون إنترنت بعد تثبيت المتطلبات. هذه الحزمة كود مصدر؛ لا تحتوي ملف exe مبنيًا على Windows.

## تشغيل Windows
1. فك الضغط في مجلد قابل للكتابة، وثبت Python 3.11 أو أحدث من python.org (مع tkinter).
2. شغّل `setup_windows.bat` مرة واحدة. هذه الخطوة تحتاج إنترنت لتنزيل المكتبات، أو مستودع عجلات محلي.
3. شغّل `run_windows.bat`.
4. عند أول تشغيل أنشئ حساب مدير وكلمة مرور من 8 أحرف على الأقل؛ لا يوجد حساب افتراضي بكلمة ثابتة.

أوامر بديلة:
```powershell
py -3 -m venv .venv
.venv\Scripts\python -m pip install -r requirements.txt
.venv\Scripts\python main.py
```

البيانات الافتراضية في `%LOCALAPPDATA%\StorePro`؛ تشمل `storepro.db` والإيصالات والأخطاء والنسخ التلقائية. لا تنقل البيانات إلى مجلد التثبيت. للعمل على بيانات منفصلة: `python main.py --data-dir C:\StoreProData`.

## البداية والاستخدام
- افتح وردية وسجّل النقد الافتتاحي من «الوردية والخزنة» قبل البيع أو الدفع النقدي.
- أضف المنتجات من «المنتجات»؛ المخزون الأولي عبر «تسوية مخزون» وسبب واضح، أو بإضافة مورد ثم تسجيل فاتورة شراء.
- نقطة البيع: اضغط على كارت المنتج لإضافته، أو استخدم البحث الفوري والتصنيفات. مسح الباركود أو كتابة الرقم ثم Enter يضيف المنتج مباشرة. عدّل الكمية بأزرار + و− أو اكتبها واضغط Enter. الإضافة السريعة تضيف وحدة واحدة أو المتبقي لو أقل من وحدة، مع إظهار الكمية المضافة بوضوح.
- الفاتورة ثابتة بجانب المنتجات؛ «تفاصيل إضافية» فيها الخصم والضريبة والعميل. الإجمالي يتحدث تلقائيًا. زر «الدفع» أو F9 يفتح نافذة الدفع: نقدي أو بطاقة أو مختلط أو آجل للمدير. النقدي يبدأ بالمبلغ المطلوب، وتعديل النقد المستلم يحسب الباقي تلقائيًا. اختر العميل للآجل، ثم «تأكيد البيع». إلغاء النافذة لا يحفظ بيعًا ولا يمسح الفاتورة. يمكن فتح وردية من نفس النافذة لو لم تبدأ وردية بعد.
- المستحق للمورد = إجمالي الشراء ناقص المدفوع. تسجيل بطاقة هو تسجيل محاسبي للدفع عبر جهاز مستقل؛ لا يتصل البرنامج بالبنك.
- المدير يستطيع المرتجعات من سجل الفواتير. أدخل صفرًا للبنود التي لا تريد إرجاعها. الدين المتبقي يُخصم أولًا حتى سقف الدين الأصلي والرصيد الحالي؛ الباقي يُسترد بالطريقة المختارة. عند تحصيل/سداد عدة فواتير الدفعات تسدد رصيد الحساب العام ولا تخصص لفاتورة بعينها.
- المدير يدير المنتجات والموردين والعملاء والتقارير والمستخدمين والتسويات. الكاشير يبيع نقدًا وبطاقة ويعرض الفواتير ويفتح/يغلق ورديته؛ الآجل والمرتجع والمصروفات تحتاج المدير.
- أغلق الوردية بالنقد الفعلي المعدود. الفرق يعرض الفعلي ناقص المتوقع، ولا يغير تاريخ الحركات. إذا كان المتوقع سالبًا بسبب مصروف/شراء لم يتم تمويله، يظهر ذلك في التسوية؛ سجل التمويل الحقيقي لتفسير العجز.

## التقارير والأسعار
الواجهة والجداول تعرض العملة والكميات العادية؛ طبقة البيانات والتصدير الخام تستخدم القروش للأموال وألف جزء للكميات. مثال: 1234 = 12.34، و1250 = 1.25 وحدة. التحويل في العرض فقط، ولا يغير قيم قاعدة البيانات أو ملفات التصدير الخام.

تقرير ملخص المبيعات يحتسب المرتجعات حسب تاريخ المرتجع، مع الضريبة والربح وفق تكلفة البنود وقت البيع. تقارير «حسب المنتج» و«حسب الكاشير» تعرض البيع قبل المرتجعات؛ راجع تقرير المرتجعات والملخص للصافي. الربح لا يطرح المصروفات العامة؛ إنه هامش البيع المعلوم التكلفة. تكلفة الشراء متوسط مرجح، والإعدادات الضريبية تحتاج ضبطًا حسب نشاطك.

## الطباعة
اختيار «فتح الإيصال للطباعة بعد البيع» في نافذة الدفع يفتح إيصال HTML محلي في المتصفح. يمكن أيضًا فتحه من «آخر إيصال» أو «إعادة طباعة» في سجل المبيعات. اضغط «طباعة» واختر طابعة Windows المثبتة. غيّر عرض الإيصال 58/80 مم من الإعدادات. يختار المستخدم الطابعة من مربع طباعة المتصفح. يجب ضبط حجم الورق والهوامش وإخفاء ترويسة المتصفح في إعدادات الطباعة. إيصال HTML يعمل دون إنترنت، ويتيح الحفظ PDF من المتصفح. تصدير التقارير PDF يدعم العربية بخط DejaVu المرفق وترخيصه.

## النسخ الاحتياطي والاستعادة
من الإعدادات احفظ نسخة يدوية على قرص آخر. النسخ التلقائية عند إغلاق الوردية تكون محلية مع احتفاظ قابل للتعديل من 1 إلى 100 نسخة؛ لا تحمي وحدها من تلف القرص. جرّب استعادة نسخة على مجلد بيانات تجريبي قبل الاعتماد عليها. الاستعادة تتحقق من سلامة الملف والمخطط وتأخذ نسخة أمان من البيانات الحالية ثم تسجل الخروج؛ الحسابات وكلمات المرور تصبح الموجودة في النسخة المستعادة. ملفات `.before-restore-*` محفوظة بجانب قاعدة البيانات ولا تُحذف تلقائيًا.

## ترحيل الإصدار الأصلي
قبل أول تشغيل على مجلد بيانات فارغ:
```powershell
.venv\Scripts\python main.py --data-dir C:\StoreProMigrated --import-legacy C:\OldStore\storepro.db
```
لا يستبدل هذا الأمر قاعدة موجودة. تؤخذ نسخة قبل الترحيل وتبقى الجداول التاريخية غير القابلة للتحويل للمراجعة. كلمات المرور القديمة تتحول لتجزئة ويُطلب تغييرها عند الدخول. نسخة ما قبل الترحيل قد تحتوي كلمات المرور القديمة النصية؛ خزّنها بشكل آمن أو احذفها بعد التحقق وحفظ نسخة حديثة.

الفواتير القديمة لا تحتوي تكاليف أو توزيعًا موثوقًا للخصم والضريبة، لذا يعرض التقرير عددها ويستبعدها من الربح المعلوم، ولا يسمح بمرتجع آلي منها. استعمل تسوية مخزون وخزنة موثقة عند تصحيح فاتورة قديمة. حركة الخزنة القديمة تبقى في جدول `legacy_cashflow` ولا تُحتسب ضمن الورديات الجديدة؛ افتح وردية بالرصيد الفعلي بعد الترحيل.

## الاختبارات وبناء Windows
```powershell
.venv\Scripts\python -m pip install -r requirements-dev.txt
.venv\Scripts\python -m pytest -q
powershell -ExecutionPolicy Bypass -File build_windows.ps1
```
بناء Windows يتم على Windows، ومخرجه مجلد `dist\StorePro` كاملًا؛ انقله كله، وليس exe وحده. تثبيت المتطلبات والبناء يحتاجان إنترنت مرة واحدة. لتثبيت مصدر بدون اتصال، على جهاز Windows مماثل متصل نفذ `pip download -r requirements.txt -d wheels` ثم انقل مجلد wheels وثبت `pip install --no-index --find-links wheels -r requirements.txt` داخل البيئة الافتراضية.

اختبارات واجهة Linux تحتاج DISPLAY/Xvfb. على Windows تتطلب سطح مكتب فعلي؛ راجع تقرير الاختبارات المرفق للتحقق الذي تم هنا. نسخة exe والطابعة الفعلية غير مختبرتين في بيئة Linux.

## حدود النطاق
لا مزامنة فروع أو تكامل فاتورة إلكترونية حكومية أو تشغيلات صلاحية في هذه النسخة. هذه تحتاج متطلبات وبيانات النشاط. لا يدعي إنشاء PDF الامتثال للفوترة الإلكترونية. التطبيق ليس نظام محاسبة عامة، ولا يشفر ملف SQLite على القرص؛ استخدم صلاحيات Windows وBitLocker لحماية بيانات الجهاز.

الباركود المكرر في قاعدة الإصدار القديم: يحتفظ المنتج ذو الرقم الأصغر بالباركود، ويُترك حقل الباركود للمنتجات التالية فارغًا. جميع المنتجات تبقى محفوظة، والباركود الأصلي موجود في `legacy_products`. يظهر تنبيه بالأرقام المطلوب تصحيحها في الإعدادات؛ عيّن باركودًا فريدًا لكل منتج قبل الاعتماد على المسح. البرنامج يمنع فتح نسختين على مجلد البيانات نفسه.

ملاحظة مراجعة: كشف حساب العميل/المورد يسجل المبلغ والمرجع، لكنه لا يحتفظ بطريقة النقد/البطاقة على سطر سداد الحساب نفسه؛ الحركات النقدية موجودة في تقرير الخزنة.
